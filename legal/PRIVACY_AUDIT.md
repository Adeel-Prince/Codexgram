# Codexgram privacy audit

**Reviewed:** October 10, 2026  
**Scope:** Repository source and configuration only. No `.env` contents, live Clerk/Convex dashboards, production traffic, vendor contract, or deployed data were inspected. The findings below distinguish app behavior from vendor-described behavior.

## Data the app asks for or handles

### Account and profile information

- Sign-up collects a name, email address, and password; email verification is requested. Sign-in uses email/password. The UI also starts Clerk hosted sign-in/sign-up, which may present Google or Apple depending on Clerk configuration: [`src/app/index.tsx`](../src/app/index.tsx#L194-L303).
- Clerk is the configured identity provider. The app passes Clerk auth to Convex and imports Clerk’s `tokenCache`; `expo-secure-store` is installed and enabled as a plugin: [`src/app/_layout.tsx`](../src/app/_layout.tsx#L1-L22), [`package.json`](../package.json#L5-L27), [`app.json`](../app.json#L30-L42). The app code does not itself define an encryption algorithm or web token-storage behavior.
- On first profile creation, the backend reads identity name, email, picture, and token identifier. It stores the token identifier, username, display name, avatar URL, timestamps, and relationship/post counts in Convex: [`convex/lib/profiles.ts`](../convex/lib/profiles.ts#L4-L57), [`convex/schema.ts`](../convex/schema.ts#L4-L20). The token identifier is an account-linking value, not shown by `publicProfile`; public profile results include username, display name, avatar URL, bio, and follower/following/post counts: [`convex/lib/profiles.ts`](../convex/lib/profiles.ts#L67-L77).
- Profile editing updates the user’s first/last name and profile image through Clerk. It stores username, bio, website, and location in Clerk `unsafeMetadata`, and also writes username, display name, and bio to the Convex profile: [`src/app/edit-profile.tsx`](../src/app/edit-profile.tsx#L131-L191). The profile screen reads that metadata, but the public Convex profile result does not return website or location: [`src/app/(tabs)/profile/index.tsx`](../src/app/(tabs)/profile/index.tsx#L96-L113), [`convex/lib/profiles.ts`](../convex/lib/profiles.ts#L67-L77). Location is user-entered profile text; no device geolocation call was found.

### Content and activity data

- The Convex schema stores profiles, follow relationships, posts, likes, comments, and stories. Post records include author, storage ID, media type/content type, caption, optional video duration, counts, and timestamps; comments include body, author, post, and timestamp; stories include author, storage ID, creation time, and expiration time: [`convex/schema.ts`](../convex/schema.ts#L4-L72).
- Users choose or capture images/videos and upload the file to Convex storage. Post captions and video duration are sent to Convex with the stored media ID: [`src/app/create-post.tsx`](../src/app/create-post.tsx#L35-L53), [`src/app/create-post.tsx`](../src/app/create-post.tsx#L99-L129). Stories upload photos to Convex storage: [`src/app/create-story.tsx`](../src/app/create-story.tsx#L20-L29), [`src/app/create-story.tsx`](../src/app/create-story.tsx#L71-L101).
- The app can request camera access for capturing posts and stories. It uses the system photo library picker. The Expo config declares photo, camera, and microphone permission text and Android `RECORD_AUDIO`; video capture is supported, so a recorded or selected video may contain audio: [`app.json`](../app.json#L22-L40), [`src/app/create-post.tsx`](../src/app/create-post.tsx#L56-L95), [`src/app/create-story.tsx`](../src/app/create-story.tsx#L20-L70).
- The code does not explicitly read contacts, precise location, device identifiers, or motion/sensor data. No EXIF stripping, face analysis, or other media-content analysis is implemented in the inspected source. Whether the native picker/OS preserves file metadata is not established by this repository.
- Social activity stored in Convex includes follows, likes, comments, counters, and timestamps: [`convex/social.ts`](../convex/social.ts#L23-L70), [`convex/social.ts`](../convex/social.ts#L73-L132), [`convex/schema.ts`](../convex/schema.ts#L22-L62).
- The Messages tab is sample data in an in-memory JavaScript store, not sent to the Convex backend by this feature; a note says demo conversations stay on the device for the session: [`src/lib/demo-messages.ts`](../src/lib/demo-messages.ts#L1-L110), [`src/app/(tabs)/messages.tsx`](../src/app/(tabs)/messages.tsx#L75-L81). This is not persistent server-side messaging.

## Where data goes and who receives it

- **Clerk:** authentication/session, sign-up identity fields, user profile name/image, and profile `unsafeMetadata` are handled through Clerk SDK calls: [`src/app/_layout.tsx`](../src/app/_layout.tsx#L1-L22), [`src/app/index.tsx`](../src/app/index.tsx#L194-L303), [`src/app/edit-profile.tsx`](../src/app/edit-profile.tsx#L175-L191). Account deletion calls Clerk’s user-deletion API: [`convex/accountDeletion.ts`](../convex/accountDeletion.ts#L30-L53).
- **Convex:** application profile records, social graph/activity, captions/comments, story metadata, and uploaded post/story media are sent to Convex: [`src/lib/convex.ts`](../src/lib/convex.ts#L1-L11), [`convex/schema.ts`](../convex/schema.ts#L4-L72), [`src/app/create-post.tsx`](../src/app/create-post.tsx#L107-L129), [`src/app/create-story.tsx`](../src/app/create-story.tsx#L78-L101).
- **Other signed-in Codexgram users:** profile and post/story data is returned by backend queries only after an authenticated profile is required. The feed, explore, post/profile views, and active stories expose content to signed-in users; the code does not implement unauthenticated public browsing: [`convex/posts.ts`](../convex/posts.ts#L107-L166), [`convex/stories.ts`](../convex/stories.ts#L25-L53), [`convex/lib/profiles.ts`](../convex/lib/profiles.ts#L4-L19).
- **Google or Apple:** hosted authentication is opened through Clerk; which methods are enabled and which identity fields they return depends on the Clerk instance and provider setup: [`src/app/index.tsx`](../src/app/index.tsx#L296-L303).
- **Unsplash:** an internal demo-seed action fetches fixed sample image URLs from `images.unsplash.com`, stores those returned images in Convex, and uses sample profile data. The call contains fixed URLs, not app-user fields: [`convex/seed.ts`](../convex/seed.ts#L7-L37), [`convex/seed.ts`](../convex/seed.ts#L220-L246). Whether this internal action runs in a live deployment is not determinable here.
- No other analytics, advertising, crash-reporting, or tracking SDK appears in the declared application dependencies: [`package.json`](../package.json#L5-L43). The inspected app/backend code contains no first-party analytics events or user behavior tracking integration.
- The Clerk provider does not set a `telemetry` option, and no telemetry-disable setting is visible in checked-in source: [`src/app/_layout.tsx`](../src/app/_layout.tsx#L18-L23). Clerk’s current docs say Clerk SDK telemetry is for development-instance SDK/component usage and does not include end-user information; production behavior and the installed SDK’s defaults must be confirmed against the actual Clerk configuration. See [Clerk Telemetry](https://clerk.com/docs/guides/how-clerk-works/security/clerk-telemetry) and [Clerk’s Expo `ClerkProvider` reference](https://clerk.com/docs/expo/reference/components/clerk-provider).

## Access, storage, and security evidence

- Convex profile/post/story functions call `requireProfile`/`requireIdentity`, so the application layer requires a signed-in Clerk identity. This is an access check, not end-to-end encryption: [`convex/lib/profiles.ts`](../convex/lib/profiles.ts#L4-L19), [`convex/posts.ts`](../convex/posts.ts#L54-L60), [`convex/stories.ts`](../convex/stories.ts#L56-L62).
- The app stores account session tokens through Clerk’s Expo token-cache integration. It does not implement client-side encryption of user content or end-to-end encryption: [`src/app/_layout.tsx`](../src/app/_layout.tsx#L1-L22), [`app.json`](../app.json#L30-L42).
- Convex states in its current platform documentation that data is encrypted at rest and that it performs regular database backups. Those are provider-reported platform practices; this repository does not configure or verify them. The actual hosting mode, region, and applicable contract are unknown: [Convex Status and Guarantees](https://docs.convex.dev/production/state#guarantees), [Convex Platform Security](https://www.convex.dev/security).
- No application-specific retention period, logging policy, backup lifecycle, data region, or administrator-access policy is configured in the checked-in source. Convex deployment logs/metrics and Clerk service-side records may be governed by provider settings and contracts; inspect those before publication.

## User controls actually implemented

- Users can edit name, username, bio, website, location, and profile photo: [`src/app/edit-profile.tsx`](../src/app/edit-profile.tsx#L163-L191).
- Users can sign out: [`src/app/(tabs)/profile/settings.tsx`](../src/app/(tabs)/profile/settings.tsx#L51-L60), [`src/app/(tabs)/profile/settings.tsx`](../src/app/(tabs)/profile/settings.tsx#L115-L117).
- Users can delete their account in Settings. The server deletes the Clerk user, then schedules batched cleanup of Convex comments, likes, follows, stories/media, posts/media, and profile. Cleanup is asynchronous, processes up to 50 rows per batch, and the code specifies no completion deadline or backup/log deletion period: [`src/app/(tabs)/profile/settings.tsx`](../src/app/(tabs)/profile/settings.tsx#L61-L87), [`convex/accountDeletion.ts`](../convex/accountDeletion.ts#L30-L55), [`convex/accountDeletion.ts`](../convex/accountDeletion.ts#L58-L184).
- A user can delete their own comments, but no individual post/story deletion function was found. Story expiry filters stories out of the active-story query after 24 hours; it does not delete story records/files: [`convex/social.ts`](../convex/social.ts#L121-L132), [`convex/stories.ts`](../convex/stories.ts#L25-L53), [`convex/stories.ts`](../convex/stories.ts#L79-L85).
- No data export/download control, privacy-request workflow, consent dashboard, ad/tracking opt-out, or account-data access screen was found. Camera/library use is mediated by native picker/permission flows; privacy, notification, and support settings are placeholders: [`src/app/(tabs)/profile/settings.tsx`](../src/app/(tabs)/profile/settings.tsx#L50-L51), [`src/app/(tabs)/profile/settings.tsx`](../src/app/(tabs)/profile/settings.tsx#L96-L112).
- Sign-up has no affirmative privacy-notice or consent checkbox/event, and the settings “Privacy Policy” row currently displays an unavailable alert rather than opening a policy: [`src/app/index.tsx`](../src/app/index.tsx#L330-L459), [`src/app/(tabs)/profile/settings.tsx`](../src/app/(tabs)/profile/settings.tsx#L106-L112).
